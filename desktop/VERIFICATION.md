# Mini-ima 持久对话、回收站与侧栏改造验收

验收日期：2026-10-15。交付为 Windows x64 Tauri 桌面程序，保留 React / TypeScript、Python / C++ 核心及原 miniima.cmd。验证使用独立数据目录和 Mock，未读取日常 API Key、未修改日常知识库。

## 已交付行为

- 新建对话和顶部加号进入空白会话并聚焦；首次发送才保存，连续提问追加消息。每个会话绑定知识库，历史跨知识库按更新时间排序，50 条分页。
- 历史恢复完整消息和每条回答的引用快照；重启恢复最近会话、草稿和未完成问题，按数据目录保存会话偏好。
- 问题先落库，稳定请求 ID 去重；失败、中断可重试，同一会话单次发送。模型只接收最近最多 8 轮、4000 个估算 token 的完整成功问答，追问结合上下文改写后检索。
- 知识库和对话统一可恢复删除；支持恢复、确认后彻底删除和清空，保留父子删除状态。CLI 新增 trash list / restore / purge / empty，kb delete 保留参数及确认方式。
- 增量迁移到数据库版本 2，升级前通过 SQLite backup 接口备份旧库。历史恢复限于数据库中仍存在的记录，不合并原有不同会话。
- 移除笔记、标签入口，新增历史列表和折叠最近文档。月亮/太阳切换主题，桌面侧栏完整隐藏/展开并记忆，窄屏继续使用抽屉。

## 打包后台与 CLI 互通

使用发布目录中的 miniima-backend.exe、本机 HTTP Mock API 和独立目录 build/frozen-smoke-4889c9e9 验收通过：

1. C++ 检索和数据库版本 2；CLI 导入后后台能检索、问答并引用实际文件。
2. 后台导入 TXT 后 CLI 可以检索；相同内容重复导入被跳过。
3. 两轮对话共 4 条消息，第二轮模型请求携带一轮成功历史；两条回答的引用使用不同快照 ID。
4. 同一请求重复发送不增加消息或 API 调用；Mock HTTP 401 保留问题，重试后恢复正常。
5. 对话删除后能通过 CLI 恢复；CLI 删除知识库后后台正常列表排除它，后台恢复后 CLI 又可查询。
6. 对话彻底删除、知识库清空、重新启动后的消息/引用一致性和后台协议退出通过。

## Windows 原生应用验收

- 原生窗口完成两轮连续提问，数据库保存 4 条消息和两份独立引用；第一轮消息未被覆盖。
- 生成中关闭出现原生确认；取消后任务继续。另一轮确认退出后，应用及完整后台进程树结束。
- 重启自动恢复原对话、深色主题和侧栏隐藏状态。前两轮引用仍可打开，来源显示实际文件名、标题路径与行 3–5。
- 中断的问题保留为 interrupted，并显示“重试问题”。重试后为 3 个问题、3 条回答，共 6 条 completed 消息，3 个不同的引用快照 ID，没有重复问题。
- CLI 将唯一知识库移入回收站后，桌面刷新显示暂无知识库；回收站仍可用。桌面恢复该知识库后，CLI 文档列表和原会话恢复可见。
- 额外写入 51 条明确标记的本地 Mock 历史，使总数为 53；实际滚动历史列表、点击“加载更多对话”访问第二页，知识库区域保持可见。
- 最终发布程序在 Mock 服务已关闭时仍恢复三轮完整消息与引用，并可离线打开其他历史和回收站。
- 检查当前对话被另一入口移入回收站后，刷新清除旧内容并提示；从回收站恢复后又可打开。刷新期间切换会话的竞态由前端测试覆盖。
