# Mini-ima 0.2 小版本更新计划

建议发布名称为 **Mini-ima 0.2**，版本标签为 `v0.2.0`。原计划 5 项，另按确认范围增加应用内更新。

## 一、新增功能

### 1. 对话重命名

- 在历史对话菜单中提供“重命名”，允许修改自动生成的标题。
- 修改后同步更新历史列表和已打开的对话标签，重启后保留。
- 空标题不保存，取消编辑保留原名称。

### 2. 历史对话搜索

- 在历史列表上方增加搜索框，按对话标题查找。
- 搜索全部有效历史，包含尚未通过“加载更多”显示的记录。
- 结果显示所属知识库，点击后恢复对应对话；清空搜索后回到原列表。

## 二、体验优化

### 3. 优化长对话滚动

- 用户停留在底部时，新消息继续自动滚动到底部。
- 用户向上阅读旧消息时，保持阅读位置，显示“回到最新”按钮。
- 当前实现会在对话或请求状态变化时直接滚到底部，建议改为根据阅读位置决定是否跟随。

## 三、问题修复

### 4. 固定发布包的文件清单

- 每次从新的临时目录组装发布包，按明确清单放入主程序、后台程序和说明文件。
- 排除旧日志、过期截图、历史验收结果及任何本地配置和数据库。
- 0.1 发布前已手动清理压缩包；0.2 将这一步纳入打包脚本，避免每次依赖人工处理。

### 5. 修复发布包说明中的失效链接

- 解压版 README 中指向源码或开发文档的链接，改为对应版本的 GitHub 地址。
- 当前发布包只包含两个程序和 README，部分相对链接指向未随包提供的文件。
- 在说明开头突出启动方法、WebView2 要求和首次 API 配置步骤。

## 实施顺序与简短验收

### 额外功能：版本检测与可选的应用内更新

- 启动检测正式版，设置页提供手动检查、版本说明与下载进度。
- 用户确认后在应用内下载、校验、退出替换并重启；可以选择稍后更新。
- 更新仅处理程序与说明，保留知识库和 API 配置，文件替换或启动失败时尝试回滚。
- 本轮只提交源码，不打包、不创建版本标签或 Release；0.1 首次升级到带更新功能的版本需手动解压。

建议顺序：**发布包修复 → 对话重命名 → 历史搜索 → 滚动优化**。

只做与这 5 项直接相关的验证：

1. 重命名后切换窗口、重启应用，标题仍正确。
2. 超过 50 条历史时，能搜到尚未加载的记录。
3. 上翻阅读期间，新回答不会把页面强制拉到底部；“回到最新”有效。
4. 压缩包文件清单准确，README 链接可访问，版本标识一致。

预计作为一个小版本集中完成，验收通过后再生成 `v0.2.0` Release。
